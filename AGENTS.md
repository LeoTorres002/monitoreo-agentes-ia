# AGENTS.md

SIAF (Sistema de Inteligencia Forestal) = "Digital forestry maquiladora" automating forest management programs (PMF) per NOM-152-SEMARNAT-2023, fully local/sovereign (no cloud LLM/geo APIs).

## Layout

- `proyecto_forestal_siaf/` — the only git repo (no commits yet; everything untracked). All agent code lives here.
- `siaf_users/{CLIENTE}/{PROYECTO}/[inputs|outputs]` — multitenant data warehouse. Gitignored, not versioned. Agents mount it at `/data/{cliente}/{proyecto}` (e.g. `inputs/csv_inventarios/inventario_campo.csv`, `outputs/tablas_nom/`, `outputs/planos_pdf/`).
- `rag_documents/` — local knowledge base, gitignored. `normativa/` (NOM-152 + manuals, **living/updated**) and `ejemplo/` (a complete finished PMF to teach SIAF, **sensitive/temporal, never exposed outside this PC**).
- `.env` at `/home/dxmdesktop/siaf/.env` — local secrets/endpoints (Bonsai API key, Ollama, RAG QA LLM). Not in the repo.

## The agents (FastAPI, one dir each, each with own `requirements.txt` + `Dockerfile`)

| Agent | Dir | Port | Key endpoint | Notes |
|---|---|---|---|---|
| Manager (orchestrator) | `agente_manager/` | 8000 | `POST /procesar` | CrewAI; runs in BackgroundTasks; spawns a llama3 crew |
| Forester (dasometry) | `agente_forester/` | 8085 | `POST /calculate` | pandas stats + fpdf2, needs `superficie_ha` in payload |
| GIS (cartography) | `agente_gis/` | 8081 | `POST /generate-planos` | Real render (logic in `cartografia.py`): reads `inputs/shape/*.shp`, draws **all** geometries (UTM, north-up) over satellite (Esri) + MDE (terrarium) + hillshade + contours; emits **4 planos** (1 localización/aprovechamiento, 2 clasificación de superficies, 3 tratamientos + sitios de muestreo, 4 uso de suelo y vegetación), each in `outputs/planos_pdf/plano_0N/` (PDF + PNG + `.qgz`), plus `tabla_atributos.csv/xlsx`. Needs pillow/numpy/matplotlib + PyQGIS/GDAL |
| Environmental (legal RAG) | `agente_environmental/` | 8082 | `GET /consultar?pregunta=` | langchain pinned `==0.2.14`; indexes **all PDFs** under `normativa/` with hash-incremental reindex + persisted Chroma |
| Compliance (auditor) | `agente_compliance/` | 8083 | `POST /audit` | Requires `outputs/tablas_nom/*.json` and ≥4 PDFs under `outputs/planos_pdf/` (recursive `rglob`); writes `REPORTE_CALIDAD_SIAF.json` |

Run any agent with `python main.py` in its dir (uvicorn binds `0.0.0.0`).

## Local LLM stack (sovereign)

- **Ollama** on host `:11434` — embeddings (`nomic-embed-text`, must exist locally) and the default RAG QA LLM. OpenAI-compatible `/v1` endpoint available.
- **Bonsai-27B-gguf** (`llama` = llama.cpp server, `~/.local/bin/llama`) — served on **`0.0.0.0:11435`** with an API key (in `.env`). Reachable from containers as `http://host.containers.internal:11435/v1`. Restart command in `.env`.
- Ports: never let Bonsai/Ollama clash with agent ports (8000, 8081-8085) or 11434. Future llama.cpp default port will move to 9931 — always pin explicitly (11435).
- `.env` is not auto-loaded by the agents; they read `SIAF_ENV_FILE` (default `/home/dxmdesktop/siaf/.env`) via python-dotenv.

## Gotchas an agent will hit

- Strictly local: venv de desarrollo en `/home/dxmdesktop/siaf/.venv` (recrear con `python3 -m venv .venv` + `pip install` de ambos requirements). `/tmp/opencode` se limpia al reiniciar: no poner venvs ni índices ahí (Chroma de dev vive en `/home/dxmdesktop/siaf/.rag_index`).
- **Bonsai 27B F16 on CPU**: `REFERENCIA_MAX_TOKENS` (default 6400) — sin un presupuesto amplio Bonsai quema `max_tokens` en razonamiento y trunca el JSON de salida (una sección de 16k chars tarda ~40-60 min). `consolidar()` trocea en bloques ≤24k chars para no rebasar ctx 8192. Bonsai razona verbosamente antes de responder AUN con `--reasoning-format none` / `enable_thinking=false`: solo apto para trabajo por lotes (destripador). Para QA interactivo (Environmental) apuntar `RAG_LLM_URL`/`RAG_LLM_MODEL` a un modelo pequeño de Ollama (`llama3`, ~8 s/respuesta).
- **Chroma persistence quirk**: langchain-chroma auto-creates a fresh collection per process unless you pin `collection_name="siaf_normativa"` (done in `agente_environmental/main.py`). If you see 0 results after a restart, a new collection got created.
- **Stale integration test**: `proyecto_forestal_siaf/test_maquila_total.py:9` POSTs Forester to `localhost:8080`, but Forester listens on **8085** (8080 is the Manager). Its payload also omits Forester's required `superficie_ha`. Don't trust it as a source of truth.
- **Ollama addressing**: containers reach host services via `http://host.containers.internal:PORT` (Podman magic hostname, so a service bound only to `127.0.0.1` is NOT reachable from containers). Pulling a new model requires working on the Ollama host, not the container. **Inverse gotcha (dev on the host)**: `host.containers.internal` does NOT resolve on the host itself — when running agents locally (not in containers), override `RAG_LLM_URL`/`REFERENCIA_LLM_URL`/`BONSAI_URL`/`ENV_CONSULTA_URL` to `127.0.0.1:PORT`, otherwise every LLM call fails with "Connection error" and validations degrade to `evidencia: ''`.
- **Destripador robustness**: `consolidar()` in `agente_referencia/main.py` falls back to local aggregation (`unicos`) when the LLM doesn't return valid flat-JSON; `aplanar()` unwraps dict-literal strings like `"{'regla': 'x'}"` that weak models emit inside otherwise-valid JSON arrays. Both make llama3 validation runs usable, but Bonsai remains the real extraction model.
- **Destripador por fases** (hardware CPU): extraer 13 secciones con Bonsai cuesta ~30 h; `EXTRAER_ONLY=1` / `CONSOLIDAR_ONLY=1` separan las fases: extracción rápida con llama3 → `agg_extraccion.json` en `referencia_siaf/` → consolidación con Bonsai (1 bloque ≤24k chars) → validación. Bonsai emite varios objetos JSON seguidos de razonamiento: `pedir_bonsai` los salva con `json.JSONDecoder().raw_decode` sobre el primer `{`.
- **Bonsai CUDA trap**: `~/.local/bin/llama` es un build CUDA; con la RTX 2070 (8 GB) `cudaMalloc` falla y aborta con `GGML_ASSERT(buffer) failed` al cargar F16 27B. Arrancar con `CUDA_VISIBLE_DEVICES=""` (fuerza CPU, ~0.75 tok/s, carga ~60 s).
- **Path drift**: containers see `/data/{cliente}/{proyecto}`; the host mirrors it under `siaf_users/`. `scripts_maquila/alta_proyecto.py` hardcodes the *production* host path `/home/ubuntu/siaf/siaf_users/...` and its `--` fails silently when run from the wrong directory — read the script before relying on it. For Environmental dev runs set `RAG_DOCS_DIR` to `/home/dxmdesktop/siaf/rag_documents/normativa` and `RAG_CHROMA_DIR` to a writable temp (defaults `/normativa` and `/rag_index` are container paths).
- **Forester CSV quirk**: `inventario_campo.csv` may carry a title row (needs `skiprows=1`), may be latin-1 encoded, and has merged cells — `UMM`/`Sitio` are forwarded-filled after numeric coercion. Tests for it are inline in the endpoint, not a suite.
- **Destripador must NOT leak the example's data**: `agente_referencia/main.py` sanitizes artifacts (CSV → only column names/shapes/null counts, JSON → keys only) before prompting Bonsai; keeps the generic reference versioned in the repo. The raw example stays only in `rag_documents/ejemplo/` (gitignored) and should be purged after validation.
- **No test/lint/type-check config exists.** No CI, no manifests beyond the per-agent `requirements.txt` (no lockfiles). Verify changes by running the agent and hitting its port.
- **GIS planos layout**: each plano lives in `outputs/planos_pdf/plano_0N/` (PDF + PNG + `.qgz`); shared rasters in `outputs/planos_pdf/_datos/` and the tile cache in `outputs/planos_pdf/_cache/`. Tile sources are overridable (`SIAF_TILE_SATELITE`, `SIAF_TILE_DEM`); set `SIAF_DESCARGAR_TILES=0` for offline runs. The 3000 m grid auto-refines for small extents. Satellite zoom is adaptive (`SIAF_ZOOM_MAX_SATELITE`=19 down to `SIAF_ZOOM_MIN_SATELITE`=15): Esri World Imagery serves uniform grey tiles where a zoom has no coverage (common at z=19 in rural areas), so `construir_satelite` steps down until it finds real imagery. Tiles (satellite **and** DEM) are requested for the **padded** extent — the WGS84 bbox of the UTM `out_bounds` via `_bbox_wgs_desde_utm` — not for the shape bbox: the 8 % margin used to fall outside the tile-aligned mosaic and left black no-data bands on the top/bottom/left edges. `SIAF_MAX_TILES_SATELITE` defaults to 900 so the wider extent still keeps the top zoom. `sat_extent` for matplotlib `imshow` must be `(left, right, bottom, top)`, NOT the GDAL `(minX, minY, maxX, maxY)` order. GIS/Compliance resolve the project dir tolerating both `<root>/siaf_users/...` and `<root>/...`. El **símbolo del norte** es el que trae QGIS (`/usr/share/qgis/svg/arrows/NorthArrow_06.svg`, fallback `NorthArrow_08`→`Arrow_02`→aguja matplotlib): `_simbolo_norte_qgis()` lo rasteriza con `QtSvg.QSvgRenderer` (los `param(fill/outline)` de QGIS se sustituyen a negro antes de renderizar) y `_simbolo_norte()` lo coloca con `OffsetImage`/`AnnotationBbox`, así que el tamaño va en puntos y nunca se deforma. La letra N se dibuja aparte, con hueco explícito (antes se empalmaba con la flecha). El símbolo va **sólo en la columna derecha** (bloque «norte + logotipo»), nunca encima del mapa: sobre la imagen satelital se perdía. `dibujar_escala_grafica()` lleva un recuadro gris (`#bdbdbd`, `alpha=0.75`, zorder 5.5) porque la barra —con sus tramos blancos— y sus números no se distinguían sobre el fondo.
- **GIS planos 2/3/4 (temática + capas base)**: los cuatro planos comparten `columna_modular()` (columna derecha con alto proporcional al peso de cada bloque: encabezado, núcleo/municipio, norte+logotipo, referencia geográfica, simbología, tenencia y superficie, marco hidrológico, elaboración), la misma cuadrícula (cruces tenues al interior + marcas completas y rótulos métricos verticales en ambos costados) y la tabla de vértices. La temática la resuelve `preparar_tema()` **por precedencia**: campo del shape (listas de candidatos + catálogo regex `TEMAS[...]["catalogo"]`, p. ej. INEGI Serie VII para el plano 4) > derivación con datos reales (`pendiente_de_dem` + criterios NOM-152 §4.7.2 para superficies; `_exg` = 2G−R−B del satélite, umbrales 30/15/0, para vegetación; tratamientos por defecto «Sin acciones»). El origen se escribe en la leyenda («shape · CAMPO» o «derivada del MDE/satélite»): **nunca** se etiqueta como dato oficial de INEGI algo que se derivó. Los sitios de muestreo del plano 3 son sintéticos (rejilla con jitter, semilla fija, círculo de 1,000 m²) hasta que llegue el CSV real. `descargar_osm()` trae además caminos, cauces (permanentes/temporales), líneas de transmisión y cuerpos de agua (Overpass `highway`/`waterway`/`power`/`natural=water`, caché en `_cache/osm/<bbox>.json`, 3 espejos × 1 intento a 30 s: si Overpass está saturado la capa base queda vacía y se avisa por bitácora — **no** se guarda un caché vacío para poder reintentar). Todo lo derivado se escribe como GeoJSON en `_datos/` (`tematica_plano_0N.geojson`, `osm_*.geojson`, `sitios_muestreo.geojson`) y **cada `.qgz` carga sólo lo suyo** (plano 1: shape+rásters; 2: +temática; 3: +temática+sitios; 4: +temática; todas con los `osm_*.geojson` si existen) para poder editarlo en QGIS.
- **GIS toponimia (OpenStreetMap)**: the planos derive real place names — nearest settlement, municipio/estado (Nominatim reverse) and colindancias (nearest settlement by **distance** per cardinal sector, Overpass `node["place"]`; the place *type* is only a tie-breaker — ranking by type first picked a village 11.9 km south over a ranch 7.2 km away) — from the map area, then write them on all planos and as editable columns (`NOMBRE_LUGAR`, `MUNICIPIO`, `ESTADO`, `COLINDANCIA_N/S/E/O`) in `tabla_atributos.*`. Priority: derived < shape name field < explicit `metadatos` in the `POST /generate-planos` payload (this is the hook for the future núcleo-agrario CSV/DB). Configure with `SIAF_GEO=0` (offline), `SIAF_GEO_RADIO_KM` (default 30), `SIAF_GEO_REINTENTOS`, `SIAF_NOMINATIM_URL`, `SIAF_OVERPASS_URL` (Overpass is flaky: it retries and falls back to mirrors — a silent failure used to leave placeholders); results are cached in `outputs/planos_pdf/_cache/geo/<centroide>.json` (delete it after changing the ranking logic). Optional LLM re-ranking of the toponymy with `SIAF_GEO_LLM=1` (`SIAF_GEO_LLM_URL/MODEL/TIMEOUT`, default **off**): with llama3 it took ~3 min and chose *farther* places, because it has no better geographic data than the candidate list. The `titulo_lienzo` (NÚCLEO AGRARIO / PREDIO) falls back to the nearest place name until the real dato arrives from a CSV/BD. This uses public OSM data only — never the sensitive `ejemplo/` names.
